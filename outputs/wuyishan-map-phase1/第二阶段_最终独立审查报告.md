# 第二阶段最终独立审查报告

审查日期：2026-09-09 至 2026-09-10。审查对象：本目录当前代码、001—010 迁移、当前本机 PostgreSQL/PostGIS 数据库及第二阶段运行配置。

**最终结论：A：第二阶段可以正式封版。**

结论基于本轮重新读取代码、真实库只读检查、随机独立库故障注入与回归、旧库升级、空库恢复和真实浏览器验证。发现的 S0/S1 已修复；没有通过降低标准忽略未修复的严重问题。封版范围为第二阶段内部管理，不包含公网部署、游客产品或第三阶段。此报告是本轮代码审查结论，不是第三方机构认证。

**当前采用“内部局域网无认证模式”，仅用于本地/家庭局域网内部管理和现场测试，不适用于公网部署。未来公网部署前必须恢复身份认证和访问控制。**

## 1. 审查范围与方法

检查 Vue/TypeScript 管理端、Node/Fastify API、共享规则、数据库结构与全部迁移、Excel 导入及历史数据整理脚本、备份恢复脚本、腾讯 GL SDK、HTTPS、排序、父子关系、主支线、地图角色、候选及正式坐标、改名历史、删除定位、软删除、回收站、子地点处理、duplicate 档案、路线/攻略/媒体/核验关联及公开坐标投影。

逐项追查 SQL 写入路径和全部 HTTP 路由；复核输入白名单、SQL 参数化、历史触发器、唯一约束、行锁和事务。没有新增产品功能、页面、数据库字段、迁移或第三阶段能力。新增代码限于审查测试与已发现缺陷的局部修复。代码文件指纹见 [审查文件清单](reports/phase2/final-audit/reviewed-files.json)。

真实库只用于读取、只读快照和备份。所有业务写入、故障注入、升级、删除/恢复实验均在随机命名的独立数据库执行，并在结束时清理；没有把任何实际地点当作测试夹具。

## 7. 坐标生命周期与误操作

- 新坐标先 pending；确认与正式记录插入同事务提交。数据库延期约束阻止“已确认但无正式记录”；新正式记录必须匹配已确认候选。
- 唯一索引保证每个地点最多一条 active；替换使旧 active → superseded，删除定位使 active → revoked，不删除地点或旧坐标，不自动复活历史。
- 历史 payload 不可 UPDATE，superseded/revoked 不可再次变更，候选观察数据不可修改，DELETE 被触发器阻止；空间字段为生成列。
- 行锁与 expected_current_id 拒绝另一页面抢先确认、替换或撤销后的旧请求；同一仍 active 候选重试不重复插入。旧历史候选不再返回误导性的成功。
- 快捷流程重复点击、候选/确认成功但响应丢失、下一地点读取失败均做浏览器验证。10 个独立测试地点保持 20 次主交互、20 次 POST、10 条候选及10条正式记录，零自动核验；自动耗时不代表人工判断地点的用时。
- 离开或刷新后已保存 pending 仍是候选，可在高级操作查看；未确认草稿不成为正式位置。数据库事务失败整笔回滚；客户端忙状态不是数据库半完成状态。

## 8. 软删除、恢复和父子关系

正常列表（含普通搜索）、内部地图、连续判点队列、子地点结果、删除窗口的新父级选项均排除 deleted；duplicate 排除正常列表/地图/队列，但可作为显式档案追溯。当前没有路线新增页面，现有新增路线入口为导入程序，本轮已补齐有效地点校验。原有路线关系继续保留，不因删除自动剔除或改序号。

无子地点删除、1 个/多个子点解绑、转移、非法目标、事务失败、恢复均有隔离测试。解绑/转移和父点软删除是同一事务；故障注入用测试序列证明子点已处理后才触发父点失败，然后核对父子表全量回滚。转移拒绝自身、任意后代、deleted、duplicate。数据库另有防环和外键。

携带正式坐标、候选、名称历史、路线、攻略、媒体、核验及核验媒体的子地点转移后，逐项核对全部关联不变，只有 parent_place_id 与既有更新时间触发器生成的 updated_at 变化。恢复父地点不会抢回子点。恢复带有仍被删除父级的地点会拒绝并要求先恢复父级。

## 9. 名称、排序、重复档案与关联

改名只更新最新 name 及既有 updated_at；触发器追加只读名称历史。连续改名、原名不重复记历史、当前/全部旧名检索、非法名称、同区域同名提示均通过。ID、WY、parent、corridor_order、坐标、路线、攻略、媒体和核验不受影响。两个相同 expected_name 的并发不同改名，一成功、一 409。

corridor_order 为独立正整数/NULL，唯一约束可延迟交换；不改 WY、parent、route_stops.sequence 或主支线角色。NULL 待排在最后，删除保留并占用原顺序，恢复不夺取别人的序号。调整在同一锁内检查 expected_order，冲突不会静默覆盖；排序操作不改 updated_at。父子层级与道路顺序保持独立。

真实 WY-0042 → WY-0041，保留编号及原攻略关联，corridor_order 为 NULL，不进入正常队列/地图。数据库阻止 duplicate 自指和链式引用。现有全部地图角色仍为 pin；没有把建议集合角色擅自写入真实数据。group/hidden 及缩放 14 级的父子显示规则在隔离浏览器用有效坐标、筛选后有效祖先覆盖验证。
