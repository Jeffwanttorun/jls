## 实际六栏目结构

| 栏目 | 内容与操作 |
| --- | --- |
| 概览 | 名称、WY ID、类型、公开版本/草稿设置、封面、草稿状态；地图、照片、简介、英文及核实提示；真实路线归属与任务快捷入口 |
| 位置与路线 | 腾讯地图选点与当前位置为主要操作；手动坐标折叠辅助区；独立导航目的地；中英文区域/地址；现有 Route → Stage → Group 归属与定位链接；创建时关联路线、阶段、分组、角色、顺序；主题 |
| 内容编辑 | 对应主题的中文/English 卡片：简介、详细介绍、为什么值得停、Jeff 实地记录；故事与研究链接；英文名称 |
| 游客信息 | 按类型调整提示、常用卡片顺序与开放面板默认展开；运营状态、开放安排及按需核实信息；实用、安全、到达、季节；设施、亲子、过夜完整编辑 |
| 照片与视频 | 封面/图集、顺序、中英文图片说明；上传/拍照；现有媒体库复用、易读名称与当前草稿使用地点数；视频标题中英文、平台与链接 |
| 核实与管理 | 实地到访、核验、官方来源、重新确认、日期；低频地图标签、简称、拼音、英文名称状态；归档/恢复、历史、备份入口 |

桌面左侧为栏目导航，中间为宽编辑区，预览按需切换。手机六栏目以触摸按钮排列。只有选中的栏目展示；同一地点对象与已打开的卡片状态保持挂载，切换栏目、语言和预览均保留未保存输入。

内容卡片先展示用途、摘要/未填写提示与编辑入口，编辑时才出现宽文本区；同一内容主题可以直接切换中文和 English。没有自动翻译或填充真实内容，段落与空行保留。不同字段没有合并或删除。

主要操作只保留一组“保存地点草稿 / 预览本地草稿”。归档、历史和备份移至管理栏目。手机保存栏使用正常文档流，避免固定栏挡住输入及软键盘区域；桌面使用原有 sticky 底栏并留出间距。保存中、未保存、成功、失败及版本冲突由现有状态机制显示。

开放情况保留原状态模型：非商业地点默认折叠，展馆优先展开；先设置运营与开放安排，再展开时段、说明、来源、日期及主动核实。正常运营不等于每天开放；编辑日期或保存不会自动确认真实信息，没有“现在营业”推断。未知亲子和过夜状态也未变成允许。

路线归属直接读取现有 membership，多路线分别显示，没有 Group 时明确“未分组”。创建时就在位置栏目选择 Route/Stage/Group；既有地点通过“查看路线中的位置”进入相应路线阶段/分组修改关系，沿用该路线编辑器的保存和离开保护，没有建立副本关系数据。

无需 migration：没有改变地点数据库和字段格式。原创建事务、编号、revision、离开保护、冲突比较、历史恢复、媒体引用、ZIP 导入导出及 PostgreSQL 完整备份全部复用。

## 列表卡片及根因

旧卡片图片的实际高度超出固定图片区，实测真实照片在 390px 下进入文字区约 **68px**。新卡片把图片限制在独立的 16:10 区域内裁切，名称、WY/区域、类型、状态、简介和主题在下方纯色文字区；没有用覆盖文字或整页隐藏横向内容掩盖问题。

名称可换行，简介约两行，无简介时低强调显示“未填写简介”。有图/无图/长名称/服务设施使用相同结构。封面按用途和顺序选择，不更改真实照片数组。主题只在显示时去重，不删除关联。

公开版本、本地未发布修改、运营/通行、开放安排、实地核实分别显示。自然地点的正常运营标签不强制展示；暂停、在建等明确状态仍保留。草稿差异由服务端即时比较 draft 与 published，兼容旧数据缺省字段，不新增状态数据库字段。列表搜索、归档筛选及离开时滚动位置保留在本浏览器会话中。

## 三个维护任务的实际路径

1. **玩水点**：列表新增 → 概览名称/类型 → 位置与路线地图选点、主题、路线/阶段/分组 → 照片与视频上传 → 游客信息填写中英安全段落 → 保存 → 中英草稿预览。切换栏目与语言后原段落、空行仍在。
2. **周末展馆**：新增或找到展馆 → 游客信息 → 正常运营/仅周末开放 → 按需补充说明、来源、日期 → 用户主动核实 → 保存 → 中英预览。“保存/设置日期”前没有自动勾选核实。
3. **路线核心节点**：打开南源岭概览 → 位置与路线查看归属 → 内容编辑打开 Jeff 实地记录 → 保存 → 预览。整个过程不需展开开放安排或高级字段。
