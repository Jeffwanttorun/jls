# 第二阶段：连续卫星判点极简化报告

已完成并重启。日常流程为：**打开无正式坐标地点 → 地图点一下 → 确认此位置 → 自动进入下一个**。没有进入第三阶段。

## 实际行为

- 从地点列表直接打开任何无正式坐标地点，默认显示卫星判点；无需点击“开始卫星判点”或进入点选模式。标准地图仍可切换。
- 地图点击立即通过原候选接口保存 pending。普通界面不要求填写来源、坐标系或精度。
- 卫星点选自动记录 `map_click`、`腾讯卫星影像人工判读`、`GCJ-02`、点选时间；测量精度保留未知，不把主观判断伪装成 GPS 精度。切换标准图时如实记录 `腾讯标准地图人工判点`。
- 位置确定度默认“高”，展开后可选中/低；分别映射现有 certain / approximate / uncertain。地图来源依据等级继续为 C，旧 A—D 定义不变。
- 唯一主按钮“确认此位置”代表用户已经人工核对落点，调用原确认接口。无正式坐标时不再增加复选框和确认弹窗。
- 成功后查询原无正式坐标队列，按 `corridor_order` 前进并保留判点视野；新页面清空上一地点选点，默认高确定度。待排地点继续标注待排。
- 可以直接点别处重选，或“撤销本次选点 / 重新点选”。被撤销或重选的本次候选标记 rejected 并保留，既不删记录，也不创建正式坐标；原有其他候选不被批量拒绝。
- 手机 GPS、手工输入、坐标系、来源详情、候选历史、替换及撤销均放入默认折叠的“高级操作”。
- 已有正式坐标时显示当前坐标提示，替换使用原高级操作中的明确确认流程，不会静默覆盖。

## 候选、事务和安全

没有修改后端坐标业务代码、数据库结构、迁移文件、P1—P5 公开投影或历史保护触发器。

仍然按原流程执行：点击产生独立 pending 候选 → 用户点击确认 → 原数据库事务人工确认候选并建立正式坐标 → 原触发器保留被替换历史。快捷流程确认携带 `expected_current_id=null`；如果其他页面已经产生正式坐标，后端会拒绝快捷覆盖，页面转为已有坐标提示。

保存中禁用重复操作；重复确认沿用候选ID和原幂等规则。候选或确认响应丢失时，先读取原记录核对结果，不盲目重建。下一地点读取失败时，仅重试进入下一个，不重新保存或确认。请求15秒超时后恢复状态提示；若无法确定保存结果，提示刷新选点状态或检查高级操作，不自动重发创建请求。

普通详情的候选状态会在选点与撤销后刷新。未确认就离开页面的候选仍保留在高级操作中，不会自动确认。

## 连续10个地点效率与误操作测试

使用随机创建的独立 PostgreSQL 测试库、真实前端和后端，以及腾讯 SDK 事件替身。测试中的坐标与地点全部是隔离测试资料。

- 10 个无坐标地点，故意让路线顺序与 WY 编号顺序不同。
- **20 次主交互**：每地点一次地图点击、一次确认。
- **20 次 POST**：10 次候选创建、10 次人工确认；另有读取请求。
- 最终 10 条候选已确认、10 条有效正式记录；每个地点只产生自己的坐标。
- 0 个额外确认弹窗，0 条实地核验，原地点资料字段完全不变。
- 自动化执行耗时 2629 毫秒，包含测试断言和截图；这只衡量本地事件流程，**不代表人工判读10个真实地点的时间，也不包含真实腾讯瓦片网络时延**。

额外覆盖：撤销/重选保留拒绝记录、中/低确定度修改、标准图来源、重复点击、候选保存响应丢失、确认响应丢失、自动跳转失败恢复、并发正式坐标拦截、明确替换及历史保留、P2—P5保护、移动尺寸及高级 GPS 入口。
