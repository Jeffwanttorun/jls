# 第二阶段补充：卫星影像人工判点

日期：2026-09-08。主要坐标建设方式调整为卫星影像人工判点，现场 GPS 保留为补充与后续核验方式。代码、迁移、测试与当前真实腾讯底图联调已完成，等待人工验收，不进入第三阶段。

当前采用“内部局域网无认证模式”，仅用于本地/家庭局域网内部管理和现场测试，不适用于公网部署。未来公网部署前必须恢复身份认证和访问控制。

## 本次完成

- 内部地图和详情点选地图均提供“标准地图／卫星影像”切换；卫星影像保留道路图层、点选和已有父子标记逻辑。
- 卫星点选保存为 pending 候选，自动记录 `source_type=map_click`、`source_reference=腾讯卫星影像人工判读`、`raw_coordinate_system=GCJ-02`。标准地图选点另记“腾讯标准地图人工判点”。来源在点击时固定，随后切换底图不会改写已选位置的来源。取消不写库，重选使用最后选点。
- 位置确定度需在保存地图候选前选择，允许“确定／大致位置／不确定”。人工确认仍需要核对地点、坐标系和落点；确认、替换、撤销保留既有事务、冲突检查和只读历史规则。
- 卫星候选可以经人工确认成为正式坐标，不要求 GPS 采集，也不会新增实地核验记录或更新最后实地核验时间。
- 地图、列表、详情增加“无正式坐标地点 · 连续判点”。按业务编号依次处理，包含从未采集、已有待确认候选及坐标撤销后无 active 的地点。确认后点击“下一个无正式坐标地点”；暂不确定可跳过。每次前进重新查询，末尾绕回未处理地点，全完成时禁用下一步。
- 连续模式把坐标管理放在详情前部，自动打开卫星判点，保留本次页面会话中的地图视野。切换地点清空选点与确定度，不沿用上一地点的位置。也可“选择待处理地点”，在列表搜索本人熟悉的地点。

## 三种信息独立记录

|信息|字段或证据|含义|
|---|---|---|
|坐标来源|source_type / source_reference|位置从哪里获得，例如腾讯卫星影像人工判读|
|位置确定度|position_certainty|操作者对落点的判断：certain 确定、approximate 大致位置、uncertain 不确定；历史未记录为 NULL|
|是否有实地核验|地点关联的 verifications / last_verified_at|依据真实核验记录显示，坐标确认不生成核验；已有地点核验记录也不能单独证明新坐标已经现场测量|

原始 Excel 的 A—D 并非独立的位置确定度：A为“实地准确位置采集并人工核验”，B为“GPS/无人机轨迹等较可靠来源”，C为“地图或卫星图人工判断”，D为“仅大致区域”。本次保留其定义和旧数据，新地图判点的 `confidence_level` 记 C。位置确定度即使为“确定”，也不会将来源等级自动升级为 A，不会宣称米级测量精度；卫星候选的 accuracy_meters 保持 NULL，并保留未知精度说明。

## 使用与待验收

2026-09-09口径更新：卫星判点及批量坐标建设以电脑端为主；手机用于现场GPS和实地核验辅助。实体 iPhone HTTPS、真实定位和地图访问均由用户确认此前已通过，不再要求手机完成卫星判点闭环。最终电脑端人工验收步骤以 [2026-09-09最终人工验收口径](最终人工验收口径_20260909.md) 为准。

电脑打开 `https://127.0.0.1:5173/map`；同一局域网手机打开 `https://192.168.2.178:5173/map`。点击“开始卫星判点”，或“选择待处理地点”搜索熟悉的现有地点。核对地点名称后在卫星影像点选，选择位置确定度，保存候选，再人工确认。检查正式记录后点击“下一个无正式坐标地点”。候选保存与人工确认仍是两个动作，不批量确认。

已知边界：卫星影像时效与实际地点落点仍需本人结合在地经验验收；确定度不是实测误差。2026-09-08测试时真实环境尚无正式坐标；父子标记自动化层级回归已通过，真实缩放属于历史现场待办，不额外扩大本次最终验收清单。实体 iPhone 不再承担卫星判点闭环验收，电脑真实地点的最终人工验收仍待用户执行。连续队列当前针对全库无正式坐标地点，按业务编号循环；地图筛选条件不缩小该队列，浏览器会话视野不跨刷新保存。

腾讯底图切换使用官方 `Map.setBaseMap`：标准 vector，卫星 satellite，并保留 base/road。核对来源：[腾讯 JavaScript API GL 地图参考](https://lbs.qq.com/webApi/javascriptGL/glDoc/docIndexMap#6)。
