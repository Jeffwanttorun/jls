# 第三阶段游客端高保真原型 V0.2 验收报告

验收日期：2026-09-10  
范围：游客端高保真可点击原型 V0.2。第一、第二阶段保持封版；本轮不进入正式第三阶段，不做公网部署或小程序开发。

## 1. 验收结论

V0.2 已达到本轮高保真原型封版条件。

- 6 个既定页面和既有产品结构保留；没有增加账户、评论、收藏、支付、推荐、天气等产品能力。
- 游客端由低保真信息页升级为 390px 主设计宽度的成熟手机网页视觉，并兼容 360px。
- 真实腾讯 JavaScript API GL 底图加载、图钉点击和地点卡片通过浏览器验证。
- 游客原型继续通过专用只读适配层读取真实数据库；浏览器测试未发送写请求。
- 第二阶段后台、后端、共享规则和 001—010 迁移文件与 V0.1 封版包/第二阶段审查指纹逐文件一致。
- 真实数据库审查前后 22 张表的行数和完整内容摘要全部一致，`.env` 摘要一致。

本报告完成后停止开发，不进入 V0.3。

## 2. V0.1 → V0.2 视觉变化

| 项目 | V0.1 | V0.2 |
|---|---|---|
| 视觉定位 | 低保真结构验证 | 面向游客的手机网页/小程序式高保真界面 |
| 品牌 | 基础色块 | 武夷山绿色、明亮背景、蓝色导航主按钮 |
| 图片区 | 简单占位 | 大幅 Hero、内容缩略图、三图拼接结构；全部明确标注“等待真实素材” |
| 首页 | 简单入口 | 品牌首屏、5 类主题卡、最近推荐横向卡片 |
| 一号风景道 | 数据式分段 | 纵向旅行时间线、路段体验、停留时长、核心点和分段地图 |
| 内容页 | 通用文字卡 | 户外、展馆、自然观察、沿途饮食四类视觉语气 |
| 漫水桥 | 简单地点组合 | 攻略停留单元、4 个真实到达点、局部地图、分步玩法、提醒、视频占位、沿路继续 |
| 地图 | 基础全屏地图 | 核心点/服务点/当前页高亮三层图钉、范围切换、底部地点卡 |

没有联网寻找旅游图片，也没有生成冒充真实地点的照片。

## 5. 地图与导航验证

- 真实腾讯 JavaScript API GL SDK 加载成功，地图 Canvas 存在。
- 捕获到 13 个成功的腾讯地图资源响应，均来自腾讯地图服务域名。
- 真实图钉点击成功，地点卡显示“兰花展示馆”。
- 地图支持“全部地点 / 一号风景道”切换。
- 核心体验点、停车/卫生间等服务点、当前页面关联地点使用不同图钉强度。
- 漫水桥导航只列出 WY-0051、WY-0052、WY-0053、WY-0009 四个现存地点，不引用已删除 WY-0008。
- 4 个内容页共 12 个导航目标逐项核对：腾讯 URI 的地点名称及经纬度均等于只读适配层返回的正式坐标。
- 外部腾讯地图 App 是否接管仍属于实体手机人工验收项；自动化只验证 URI 结构和目标。

证据：[真实地图结果](reports/prototype-v0.2/real-map-results.json)、[游客端浏览器结果](reports/prototype-v0.2/browser-results.json)。

## 9. 本轮产品代码变化

产品运行代码只涉及 `prototype/`：

- 扩充页面内容配置的视觉元数据；
- 新增统一素材占位组件；
- 升级首页、路线时间线、4 个详情页、全屏地图、地点卡、导航抽屉和固定底栏；
- 更新移动端响应式样式和页面标题；

`tests/`、`scripts/` 和 `reports/` 的新增文件仅用于验收、指纹比对和交付，不构成产品功能。

## 10. 已知视觉问题

1. 项目内没有可确认授权且能对应这些真实地点的照片与视频，现用统一“等待真实素材”占位。接入用户真实素材后需再检查裁切、亮度和文字可读性。
2. 全路线地点较密，当前地图图钉在部分缩放级别会聚集；V0.2 保留既有简单地图能力，没有新增聚合、搜索或路线规划。
3. 自动化覆盖 Edge、Chromium 和 WebKit 内核；不同实体手机的系统字体、底部安全区和外部腾讯地图 App 接管仍应以实机为准。
4. 内容文案属于原型配置，未擅自扩写展馆历史事实，也未引入评分、榜单或虚假评价。
