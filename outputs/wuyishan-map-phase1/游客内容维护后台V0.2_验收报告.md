## 2. 持久化方案、隔离与未来迁移

采用独立原子 JSON store：当前数据 `visitor-content-store/data.json`，种子 `visitor-content-store/seed.json`，备份 `visitor-content-store/backups/`。写入时先备份旧文件，再写随机临时文件，校验后 rename 原子替换。store 有整体 `version`，内容、主题映射、提醒有对象 `version`，接口使用 `expected_version` / `expected_store_version` 防止旧页面静默覆盖；进程内写入串行，任一步失败不发布半成品。

选择文件 store 是因为当前是单机/家庭可信局域网、单人维护、数据量小的 V0.2 原型。它与第二阶段 PostgreSQL/PostGIS 完全隔离。未来可按 `themes / content_units / content_versions / content_place_links / navigation_targets / alerts / history` 迁移 PostgreSQL，稳定 UUID、placeCode、版本和历史可保留。

游客写接口没有 PostgreSQL 写语句。地点目录、合法导航目标和坐标状态均只读查询；游客 store 只引用 `WY-xxxx`，不复制坐标。

## 3. 内容单元结构

内容单元包含稳定 UUID、版本、草稿/已发布/隐藏、回收状态、更新时间和发布时间；内部名称、游客标题、一句简介、slug；多个主题、适合带孩子、主题内顺序；多个组成地点、角色和顺序；默认及其他导航目标；关联提醒；简单内容模块及顺序；工作草稿与已发布快照。

visitor content unit 与 place 独立。一个内容可关联一个或多个地点，也可没有自己的地点坐标。“漫水桥怎么玩”继续存在，但没有恢复 WY-0008，而是由仍有效的停车、卫生间、河滩等地点组成。

## 4. 游客主题与组合筛选

主题为玩水、风景、自然、茶、展馆、吃点东西。地点和内容单元均为多对多映射，不写回 `places.category`，也没有名称、关键词或 AI 自动归类。

“适合带孩子”是独立筛选。`主题 + 适合带孩子` 使用交集，不做集合相加。后台支持按地点一次勾选多个主题和适合带孩子后一次保存；也支持按主题批量勾选正常地点和内容单元后原子保存。主题内顺序独立保存，不借用 `corridor_order`。

月亮湾当前为：风景 + 自然 + 适合带孩子；不属于玩水。提醒为“这里可以看水景，但禁止下水。”，级别“注意”，状态启用。

## 5. 发布、预览与游客动态读取

流程为编辑 → 保存草稿 → 预览 → 发布。草稿不进入普通游客接口，预览读取指定内容的当前草稿。编辑已发布内容时，保存只更新工作草稿；发布后游客端刷新动态读取新发布快照，无需重新 build。隐藏后游客不可见，后台数据、发布快照及历史保留。删除只进入游客内容回收区；恢复不会恢复任何 place。

## 6. 现场提醒

提醒支持提示/注意/重要三级、启用/关闭、可选起止时间、关联多个地点和内容。到期后游客接口自动停止返回，历史不物理删除。游客端在内容靠前位置显示有效提醒，并按级别使用不同但克制的视觉样式。

## 7. 导航目标

内容支持一个默认导航和多个其他导航，可改显示名称、顺序、默认项和移除。发布前必须有默认导航。服务端只接受未删除、非 duplicate、具有当前正式坐标的 place。

store 仅保存 placeCode，不保存经纬度。坐标关系为 content → place → 当前 active 正式坐标，禁止使用 candidate、superseded、revoked、回收站地点或猜测坐标。

## 8. 组成地点及角色

关系角色包括主要体验、第二体验/下一部分、停车、卫生间、导航、附近服务、其他；关系有独立顺序，不依赖 corridor_order。停车和卫生间可出现在内容详情的“到了以后怎么办”，不会因此成为主题一级卡片。

## 9. 检查中心与搜索

检查只发现、提示、跳转，不自动修复。规则覆盖：已发布无主题、已发布无默认导航、无组成地点、引用不存在/回收站/duplicate 地点、导航失效或无当前坐标、在建地点相关已发布内容缺少明确提醒。每项可直达对应内容分区。最终当前问题数为 0。

搜索覆盖内容标题、内部名称、简介、地点当前名称、历史名称和 WY 编号；地点命中会提供主题维护入口并找到相关内容。

## 10. 并发、历史与备份恢复

对象及 store 乐观锁在版本冲突时返回 409：“内容已经被更新，请刷新后重新确认。”批量主题修改在一次 mutation 内全部成功或全部失败。历史保存时间、对象、变更类型、前后摘要。每次写入前自动备份；列表提供手动导出；恢复能力已在随机临时 store 中验证。最终完整备份位于 `visitor-content-store/backups/`，文件名以 `final-v0.2-` 开头。

## 11. 界面与手机维护

后台延续品牌绿色、白色和浅中性色，使用宽内容区、轻量卡片、小状态标签和清晰按钮层级。内容列表不是横向数据库表，不暴露 UUID、PostGIS、P 等级或坐标历史。编辑页按基本信息、游客怎么找到、到了以后怎么办、现场提醒、页面内容组织。保存/预览/发布突出，复制/隐藏弱化，删除保持低权重危险样式。

手机端使用卡片与可触摸按钮。已验证 390×844 和 360×800，无横向滚动；搜索、主题/适合带孩子、提醒、默认导航、发布和隐藏均在浅层页面可达。复杂长篇编辑仍以电脑端为主。

## 16. 已知限制

1. 文件 store 适用于单个 Node 服务进程和单人维护，不适合作为多服务实例并发写入的公网架构；正式迁移 PostgreSQL 后应使用事务和行版本锁。
2. 当前为家庭可信局域网内部维护模式，没有公网级身份认证与访问控制，不得直接暴露公网。
3. 模块和关系排序使用上移/下移，没有增加拖拽动画。
4. 后台提供手动导出，恢复 API/store 已验证；为避免误恢复，未增加醒目的网页一键恢复按钮。
5. 自动化通过不能代替本人对内容语气、手机触感和操作路径的判断。

### 20.2 图钉裁切与锚点

原 SVG 图钉路径使用固定 30px 的圆弧水平位移，而普通图钉容器宽度也是 30px，导致路径及白色描边超出纹理边界；焦点图钉与其他尺寸也无法保持统一几何关系。腾讯 `MultiMarker` 会按 `MarkerStyle` 的纹理尺寸绘制，超出部分因此被裁切。

现改为按每种图钉尺寸计算 SVG 路径，并在四周保留 5px 透明安全边距。`MarkerStyle` 宽高与 SVG 画布完全一致，锚点横向居中，纵向对应图钉尖端最下缘。经像素边界检查，普通、服务、焦点和弱化图钉均没有像素贴住纹理边缘，锚点与实际尖端相差不超过 1px；没有改变任何经纬度。

已覆盖普通 marker、当前选中 marker、单地点地图、组合内容地图、主题地图、一号风景道地图，以及路线缩放后显示的服务点。图钉视觉尺寸没有缩小。

### 20.3 移动端底部抽屉

地图地点卡改为真正的底部抽屉：

- 默认高度按当前实际可视区域的比例计算，保留地图主体，同时直接显示缩略图、类型、完整地点名称和“导航到这里”；
- 点击抽屉手柄或向上滑动手柄可展开，向下滑动可收起；
- 内容超过抽屉高度时只在抽屉内部滚动，地图区域继续独立拖动和缩放；
- 抽屉使用 `overflow-y:auto`、移动端惯性滚动、`overscroll-behavior:contain` 和 `touch-action:pan-y`；
- 底部留白包含 `env(safe-area-inset-bottom)`，最后一行内容可以滚动到可见区域；
- 全屏地图优先使用 `window.visualViewport.height` 同步真实可视高度，并保留 `100dvh` 和 `100vh` 回退，不再只依赖固定 `100vh`；
- 关闭抽屉后卡片完全移除，地图仍占满当前可视区域，没有空白遮罩或不可点击层。

顶部当前对象条允许地点名称两行显示。齐云峰显示为完整的“齐云峰观景/日出位置”，核心名称不再被省略号截断。
