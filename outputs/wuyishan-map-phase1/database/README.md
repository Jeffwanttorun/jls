# 数据库结构与迁移映射

数据库采用 PostgreSQL + PostGIS。`001_initial.sql` 创建核心结构；`002_integrity.sql` 增加无顺序路线关联、有限时间约束等完整性规则。执行器记录每个迁移文件的 SHA256，重复执行不重复建表，已执行的迁移文件不能静默修改。

## 对象与关系

|对象|用途及主要约束|
|---|---|
|places|UUID 内部主键，`code` 唯一且不可修改，保留 WY-xxxx；父地点外键和防循环触发器；类型、状态、公开等级、优先级为数据库枚举|
|taxonomy_terms|保存分类标签工作表的维度、编码、名称、说明及启用状态；业务键为维度+编码；地点主分类必须引用已启用的一级分类|
|place_coordinates|原始和地图坐标分列；保存来源类型、原文件、时间、精度、可信等级、转换方法及确认审计；未确认行可留后台，但不会进入正式坐标视图|
|coordinate_candidates|外部坐标接收区；业务编号、原始来源、目标地点、匹配置信度与依据、转换结果、人工确认审计和拒绝原因均保留|
|place_practical_info|车辆、道路、步行、停车、厕所、餐饮、饮水、信号、充电信息，地点一对一|
|place_accessibility|推车、背带、年龄段、老人、台阶、遮阴、座椅和风险，地点一对一；额外保留来源的笼统“适合带娃”评价，不能推断年龄段评分|
|place_nature|自然观察、时令天气和敏感性；保证看到默认 false|
|place_water|水深、河床、水流、降雨风险、儿童下水和最后水情核验时间|
|verifications|每次核验独立记录；只允许新增，禁止更新和删除；地点最新核验通过实际历史记录聚合得到|
|routes|路线业务编号唯一且不可修改；保留来源状态、起终点文字、候选性质；首次导入全部草稿|
|route_stops|路线+序号复合主键，地点外键；支持停留时长、必选/可选、替代组与条件；来源空白不推断必选|
|route_place_links|地点库“关联路线”中的明确无顺序关联，与 route_stops 区分，不能当作导航顺序|
|guides|攻略业务编号唯一且不可修改；正文、摘要、正文来源、内容进度与发布状态分开|
|guide_places / guide_routes|攻略与地点/路线多对多；关联路线攻略可在路线站点详情中列出|
|media|媒体类型、用途、文件地址、本地原始路径、拍摄时间、方向与公开状态；默认私有|
|verification_media|规范化保存规格中的 photo_ids；Excel 现场照片索引还没有真实媒体对象，因此保留为 source_photo_note，不伪造媒体主键|
|import_jobs / import_rows|任务、源文件 SHA256、预览 SHA256、工作表、原 Excel 行号、原始单元格及公式缓存、逐行结果和问题明细|
|schema_migrations|已应用迁移文件名、内容摘要、执行时间|

`places.tags` 为文本数组，可按标签查询；一级分类和受控枚举由独立字典及数据库类型约束。标签源字符串完整保留在导入原行中，按 `/` 拆分形成现有自由标签，不自动改写为新的分类规则。

## 坐标与接口边界

- DJI、GPS、手机、地图点选和手工导入都保留原始来源；Excel 坐标全部先进入候选表，不直接写 `place_coordinates`。
- 原始 WGS84 才生成 `geography(Point,4326)`，有 GiST 索引。GCJ-02 地图结果使用 SRID 0 的 geometry 和显式坐标系列，绝不伪装成 EPSG:4326；原始 GCJ-02/BD-09 不生成 WGS84 geography。
- 未知坐标系可保存原始候选，不能接收转换结果或正式导航。当前阶段没有实现坐标转换算法和确认写回操作。
- 坐标成对、经纬范围、精度非负、地图坐标系及确认人/确认时间由 CHECK 约束保证。
- Excel 的确认勾选只存 `source_claimed_confirmed`，没有确认审计凭证就保持 `human_confirmed=false`。不能将“是否人工核验”直接视为坐标正式确认。
- `confirmed_place_coordinates` 只读取经人工确认的 GCJ-02 地图坐标，并选取最新确认记录。
- `public_places` 仅返回明确定义的少量字段：P1 且状态正常才能带正式坐标；P2/P3 仅返回区域文字；P4 无区域无坐标；P5 不存在于公开投影。P2 的模糊区域图形留待后续人工确定，本阶段不生成虚假模糊坐标。
- `/api/places` 和 `/api/places/:code` 使用安全投影，不返回原始坐标、来源、备注、媒体、父子对象或关联对象。本阶段仅验证未来正式接口契约，未开发游客端。
- `/api/admin/*` 当前采用内部局域网无认证模式，可读取完整精确来源；响应 `Cache-Control: no-store`。API 默认仅监听 127.0.0.1，通过管理端代理供局域网访问。仅限本地/家庭局域网内部管理与现场测试，公网部署前必须恢复身份认证和访问控制。
- 子地点的公开等级独立判断，父地点公开不使子地点自动公开。关闭、施工和待核实等非正常状态均没有导航坐标。

|来源工作表/列|入库位置或处理|
|---|---|
|分类标签：维度、编码、名称、说明、启用|taxonomy_terms，完整 33 行；任务枚举只是字典，不建立任务业务表|
|地点库：地点ID、名称、层级、父ID、区域、分类、标签、等级、状态、优先级|places 对应列；父业务编号解析为内部 UUID|
|地点库：原始/地图坐标、坐标系、来源、可信等级、是否人工核验|coordinate_candidates；确认声明单独保存；来源工作簿名及行号可追溯|
|地点库：最后核验日期|places.source_last_verified_at，仅作原始来源声明，不生成历史核验|
|地点库：距今核验天数、信息新鲜度|公式及缓存留在 import_rows；业务接口根据 verifications 重新计算，0—90 天新鲜、91—180 天建议复核、181 天及以上过期|
|地点库：停车、厕所|place_practical_info，空值仍为空，不将未知写成“否”|
|地点库：适合带娃、适合老人|place_accessibility 的来源评价、elderly_friendly；不推断分龄评价|
|地点库：雨天适合、主要风险、一句话说明、备注|places.rain_friendly / risk_note / intro / notes|
|地点库：关联路线/攻略|route_place_links / guide_places，解析业务编号；无顺序的关联不生成站点顺序|
|路线库：地点序列|按明确的 `→` 序列建立 route_stops，sequence_confirmed=false；R-0004 保持无站点序列|
|路线库：预计总时长、驾驶时长|必须写明确单位，如 30分钟、2小时；转为分钟，裸数字报错，避免误把小时当分钟|
|路线库：步行距离km|转为米；当前源表三个时长距离字段均为空|
|路线库：状态、雨天可用、起点、终点、季节、适合人群、备注|分别保存；“部分”保留为部分，所有路线发布状态为草稿|
|攻略库：发布状态|原进度存 source_workflow，publish_status 统一草稿；“已有内容/待入库”不等于已发布|
|攻略库：正文文件/链接、封面/素材备注、备注|body_source / media_note / notes；不读取外部链接、不把备注生成正文；平台原值留在导入原行，业务模型不依附平台|
|实地核验全部列|按字段写 verifications；“水情/自然观察”保留为原始合并观察说明，未随意拆解；照片索引保存文字；缺人或时间报错|
|坐标候选匹配全部列|保存原始文件、类型、时间码、设备、海拔、原始坐标、匹配目标与理由、候选转换结果；原声明和写回状态均留审计原行|
|项目总览、待核验任务、坐标导入规则|保留原 Excel，作为迁移参考；不建长期任务业务表；23 项待核验任务未冒充现场核验记录|

本文件所列之外的原始单元格均保留在 import_rows.payload。没有源值的短名、主线、专业实用字段、自然观察和水域专业字段保持空值或没有扩展记录。

## 导入流程和重试

预览读取文件和当前数据库，验证表头、必填项、重复编号、枚举、格式、父子循环、分类和路线/攻略引用。首批源文件采用 SpreadsheetML 命名空间前缀；读取器只在内存中规范化 XML 并忽略绘图/表格展示元数据，以兼容 ExcelJS。源文件不改写，并已用独立 Python 读取核对 1,817 个单元格。

预览报告包含内容摘要。apply 重新读取源文件与数据库，任何影响计划的变化都会要求重做预览。通过预览后按分类、地点、路线、攻略、核验、候选顺序执行；地点额外按父先子后排序。每一行连同其关联数据使用单独事务，错误回滚本行后继续其他行。已有业务编号默认跳过，未提供更新开关。

数据库断连或进程强制退出属于任务级故障，任务可能保持 running/pending；已经提交的行保留，恢复连接后重新预览并导入，唯一编号阻止重复覆盖。当前不提供自动恢复守护进程。
