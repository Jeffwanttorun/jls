# 一号风景道真实道路路线修正验收报告

验收日期：2026-09-11  
版本范围：第三阶段游客端高保真原型 V0.2 的“一号风景道”路线几何修正  
结论：代码与自动化验证已通过，七组真实腾讯地图截图已生成；等待手机人工验收。本轮未增加其他功能，未进入 V0.3。

## 1. 原实现为什么错误

未通过验收的版本使用 44 个近似点表达路线。这些点受到地点分布和人工插值影响，不能证明折线位于实际公路中心线上。山区道路弯曲密集，少量点之间直接连线会切过山体、河道或建筑，因此“沿途地点的逻辑顺序”被错误地当成了“道路空间轨迹”。

现已彻底取消 `corridor_order / POI 坐标 → Polyline` 的生成关系：

- `corridor_order` 仅表达地点沿线先后；
- 地点代码仅用于图钉显示和筛选；
- 路线使用独立、只读的道路 geometry；
- 停车场、卫生间、河滩、展馆建筑点和武夷源支线均不能拉动主线；
- 地点图钉允许与道路有实际距离，不修改地点坐标去贴线。

旧报告 [游客地图路线与主题分类修正_验收报告.md](游客地图路线与主题分类修正_验收报告.md) 已在首页标注其 44 点路线结论作废；其中主题分类结论不受本次修正影响。

## 2. 新路线 geometry 来源

### 2.1 真实轨迹检查

已对项目素材进行只读检索，没有发现可确认覆盖“南源岭 → 坳头村”的完整驾车 GPS、GPX、KML、KMZ、FIT、TCX、NMEA、DJI SRT 道路轨迹。无人机飞行数据即使存在也不会被当作道路轨迹。

### 2.2 腾讯路线来源

本次采用 **腾讯地图官方驾车路线规划结果**。在腾讯地图官方路线页面取得一次路线结果后，将其解压并固化为游客端只读缓存。腾讯官方文档说明驾车接口返回 `routes[].polyline`，首对坐标为绝对值，后续为百万分之一度的差分值；本次按该规则解码。参考：[腾讯位置服务路线服务 API](https://github.com/TencentLBS/tencentmap-webservice-skill/blob/main/references/api-direction.md)。

选定路线的腾讯返回信息：

| 项目 | 结果 |
|---|---:|
| 坐标系 | GCJ-02 |
| 总距离 | 64,277 米 |
| 预计驾车时间 | 110 分钟 |
| 解码后道路点 | 952 个 |
| 路线范围 | 南源岭方向 → 坳头村 / 坳头观景台方向 |
| 腾讯返回关键道路 | 江东路、武夷山国家公园1号风景道 |
| 一号风景道路段 | 约 51.7 公里 |
| 游客打开地图时实时规划 | 否 |

路线不是仅凭起终点后直接接受：取得候选路线后，使用南源岭、星村、黄村、月亮湾、桃源峪方向、大峡谷展示馆附近、坳头村七个控制位置检查走向；同时核对腾讯返回的关键道路名称，并在真实腾讯底图上逐段肉眼检查。控制位置只用于选择、审计和分段，不替代道路点，也不把 POI 坐标写进折线。

主线路径靠近沿途核心区域，但不会为经过建筑或体验点而离开道路。例如当前几何到黄村乌龙茶展示馆约 351 米、红茶发源地展示馆约 506 米、大竹岚自然观察区域约 515 米；这些距离被保留，证明 POI 没有把公路线拉向自身。

## 3. API 限制与处理

当前项目腾讯 JavaScript API GL Key 可以加载真实底图，但直接调用腾讯 WebService 驾车接口返回状态码 `199`，含义为该 Key 未开启 WebService API；当前加载的 JS SDK 也没有可直接使用的 `DrivingService`。

因此本轮没有在每次游客访问时调用路线规划，也没有降级回地点直连。处理方式是：通过腾讯地图官方路线页面取得并核对一条实际驾车道路 geometry，一次解码后固化。这样既保留腾讯道路规划结果，也避免 Key 能力限制、访问速度、配额和未来推荐线路变化影响原型。

原始返回证据保存在 `reports/route-theme-v0.2/tencent-route-raw.json`；生成后的来源摘要保存在 [source-summary.json](reports/route-geometry-v0.2/source-summary.json)。原始响应只用于复核和重新生成，不在浏览器运行时加载。
